# 内容加载与过渡（Loading & transitions）

> 悬停静默预取、180ms 原子提交、300/500ms 防闪律与同构骨架交叉显影，彻底消灭切换白闪与砸屏。

页面与内容切换卡顿、白闪、布局乱跳，往往不是接口太慢，而是「先清空成空壳，几十毫秒后再把整屏内容硬砸进 DOM」。本官网文档页的每次切换都已实装以下五条加载过渡规范。

## 为什么内容切换显得生硬

- **空壳抢跑**：路由一变就立刻把主区和右侧目录清空，哪怕数据 40ms 后就回来，用户眼睛也先挨了一记白闪。
- **骨架高频闪屏**：没有延迟宽限也没有最小驻留，120ms 的请求先闪出一帧灰色条再瞬间切走，比不加骨架更刺眼。
- **尺寸塌陷跳动**：占位框高度远小于真实内容，演示或接口回来时把下方文档、代码与目录整块往下推。
- **孤立生硬硬切**：新内容零过渡直接拍在脸上，缺少视觉承接与阅读视线引导。

## 五条核心时序规范

| 阶段 | 时长与阈值 | 设计目的与实现方式 |
| --- | --- | --- |
| 悬停静默预取 | pointerenter / focusin | 在指针移向导航项到真正点下去的 100–250ms 间隙里提前缓存数据，90% 的点击在 0ms 内完成数据就绪。 |
| 原子提交宽限期 | ≤ 180ms | 路由切换时不立刻清屏；若目标数据在 180ms 内就绪，直接带着完整正文与目录一次性原子提交并做交叉过渡。 |
| 加载态延迟阈值 | 300ms | 300ms 内能返回的局部异步块（按钮等待、演示框占位）不展示任何转圈或骨架，避免视觉噪声。 |
| 骨架最小驻留 | ≥ 500ms | 一旦超过延迟阈值展示了骨架，至少平稳驻留 500ms 再交叉淡出为真实内容，杜绝一闪即逝的闪烁感。 |
| 微位移交叉显影 | 220–240ms · ease.outStrong | 真实内容就绪时，仅通过 opacity（0 → 1）与微小位移（translateY 6px → 0 / scale 0.994 → 1）柔和落定。 |

## 对错对照

**这样做**：指针经过目录项就预取数据；180ms 内一次渲染完整标题、正文与本页目录；慢网时展示与段落/演示高度对齐的同构呼吸骨架，数据就绪后平滑交叉显影。

**不要**：一点击立刻清空右侧正文和目录，先显示"正在加载…"和孤零零的转圈，50ms 后把整页内容猛砸进 DOM，导致页面和滚动条剧烈跳动。

## 本官网已实装的机制

- **全站元数据缓存与预取**：左侧目录监听 `pointerenter` 与 `focusin`，静默预热组件契约 JSON、配方 Markdown、规则与令牌表。
- **View Transitions 原子提交**：换页前先等待缓存/预取最多 180ms，确保过渡画面的新帧已经带有完整章节与右侧本页目录，绝不向空壳做过渡。
- **演示框记高 + 柔和显影**：已测过的演示框高度缓存在本地，再次访问直接按真实高度占位；加载态使用极轻柔和微光骨架并自带 300ms 延迟，演示就绪后平滑淡入。
- **尊重减少动态效果**：开启 `prefers-reduced-motion` 或 `.sn-reduce-motion` 时自动移除位移与缩放，仅保留瞬间或极轻的清晰切换。
