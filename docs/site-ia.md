## 每一项为什么放在那里

| 位置 | 为什么 |
|---|---|
| 顶栏五项：文档 · 组件 · 规范 · 配方 · 给 AI 用 | 对应五类来访的目的：装起来用、找一个组件、看规矩、照着搭整页、交给编码助手。每一项进到这一类的第一页（文档 → 快速上手，组件 → 组件总览，规范 → 设计原则，配方 → 配方总览，给 AI 用 → 安装与用法），不跳进某一个具体组件，也不跳回首页的某一节 |
| 顶栏右边：照基线 | 用户要求两个顶栏除导航文字外和原版一模一样（2026-11-21）。首页：搜索图标（⌘K）、单个深浅切换、"开始使用"；文档页：搜索框"搜索组件 ⌘K"、主题调整、深浅切换。"跟随系统 / 浅色 / 深色"三态在页脚、首页主题区、窄屏抽屉底部的分段控件里 |
| 去掉"展示页" | 展示页（index.html）是设计稿和内部对比用的，排版、说明都是给开发看的；官网所有内容在文档里都有，留着入口只会把人带到半成品。演示框照旧用 `?embed=` 嵌展示页的那一块，不算露出 |
| 去掉"主题 → 首页#theme" | 文档页里点"主题"跳回首页，用户不知道自己在哪；换主题用顶栏的主题调整按钮，讲怎么定制在"定制 → 主题" |
| 开始：介绍 → 快速上手 → 用 CLI 创建项目 → 框架接入 → 移动端与 H5 → 浏览器支持 | 按第一次用的顺序：知道是什么、装起来、或者一条命令起项目、换成自己的框架、上手机、确认浏览器 |
| 定制：主题 · 深色模式 · 令牌 · 多语言 · 图标 | 都是"在不改组件的前提下改成自己的样子"。原来"主题定制"一页讲了主色、深色、局部主题，拆成主题和深色模式两页；令牌表直接从令牌文件生成；多语言、图标的用法原来没有 |
| 给 AI 用：安装与用法 · AGENTS.md · 检查器 · 评测结果 | Satin 的定位是给 AI 用，这一组单独成区：装技能、写进项目说明、自己检查、看效果。原来挤在一页里，拆开后每页讲一件事 |
| 规范 13 章 | 不变：数值写清楚的设计规矩，组件页的"要点"引用这里 |
| 组件：组件总览 + 按类别 | 总览按类别放卡片，先看全貌再进具体组件；顶栏"组件"不再直接跳到"按钮" |
| 配方：总览 + 8 种 | 配方是整页骨架，和组件是两个层级，单独成区；每一种有实时预览、代码（HTML / React / Vue）和补充说明 |
| 其他：更新日志 · 路线图 | 不常看但要能找到；内容都是真的（还没发布的写"未发布"，不编版本号和日期） |
| 窄屏抽屉 | 和左边目录同一份清单、同样的分区：分区标题是小号灰字，只有"组件"下面的类别能折叠（缩进、带箭头），当前类别展开；底部是外观和主题调整 |
| 首页按钮 | "快速上手"和"用 CLI 创建项目"是两种开始方式；"看全部组件" → 组件总览 |

## 规矩

- 导航项的名字和它进到的页面标题一致（顶栏五项是分区名，进到分区的第一页）。
- 文档页里不跳回首页的某一节；没有空链接、假数据（不放假的 GitHub 星数、客户 logo）。
- 还没做到的写清楚：CLI 和 npm 包还没发布，"用 CLI 创建项目"页和首页命令旁边都注明了，发布要用户确认。

## 框架偏好：一个官网服务所有框架（2026-11-21，用户要求，替代"每块代码各自切写法"）

**目的**：不懂开发的人和低档 AI 到官网先选自己用的框架，之后看到的每一段代码都能原样复制进自己的项目跑起来。所以：

1. **全站只有一个"框架偏好"**：HTML（原生）、React、Vue、Svelte、Angular、Solid、Preact。Next.js、Nuxt 不是另一种组件写法，是 React、Vue 的运行环境，做成它们下面的"环境"子选项，只影响安装、接入、CLI 那几页。
   - 入口：文档侧栏顶上（钉住）、每个跟着框架变的代码块头部；手机放在抽屉底部。**不放进顶栏**，选择器用官方标志、不写"框架："字样，Next.js / Nuxt 不进选择器（是快速上手、接入页里的"Vite | Next.js"页签）。换的都是同一个全站偏好。
   - 记在 localStorage（`satin-fw`），网址参数 `?fw=vue` 优先（分享链接时对方看到的是同一种写法）。
   - 换了以后页面不刷新：只重画代码块，滚动位置不变。快速上手的安装和引入、框架接入、组件页、配方页、CLI 页（`init --framework` 的默认值）一起变。
2. **代码只有一个来源，而且是测过的**：组件页、配方页的代码直接读 `examples/<框架>/` 里这个演示的源码文件（全量示例本身）。全量示例由 `scripts/examples/gallery.mjs` 生成、构建、逐块截图和设计稿比对——官网上显示的就是这些文件，所以复制就能跑，不会出现 61 × 7 份手写代码互相走样。
3. **能加框架**：框架登记表 `site/frameworks.js`（名称、组件文件后缀、高亮语言、示例目录、演示文件的路径规则、安装命令、接入页里的那一节、环境子选项）。加一个框架 = 加一条登记 + 在 `scripts/examples/gallery.mjs` 里加这个框架的生成函数 + 建 `examples/<框架>/`；官网的选择器、代码块、接入页自动多出这一项，不用改页面代码。
4. **没有对应写法时明说**：某个演示在当前框架下还没有专门的写法，代码块上写清楚（比如"Svelte 暂用自定义元素写法"），给出能直接用的自定义元素代码；绝不悄悄显示另一个框架的代码。
5. **现场演示不变**：演示框里仍然是真组件（展示页的那一块）；代码块头上标明当前框架和文件名（"Vue · ButtonDemo.vue"）。

### 为什么这样设计

- 用户和低档 AI 的问题不是"看不懂四种写法"，而是"不知道哪段能用在自己的项目里"。全站一个偏好，选一次，之后所有代码都是自己的框架，复制就能跑。
- 代码取自构建、截图过的示例，正确性由自动测试保证，而不是靠人对照。生成的代码出错，示例构建和截图对比会先失败。
- Next.js / Nuxt 和 React / Vue 的组件写法完全一样，只有装法和接入不同；放成子选项避免组件页出现重复的两份。

### 加一个框架的步骤

1. `site/frameworks.js` 加一条：`{ id, name, ext, lang, dir, demo(id, n), install, setup }`。
2. `scripts/examples/gallery.mjs` 的 `WRITERS` 里加这个框架：给一个演示（标记、接线脚本、演示样式），写出组件文件；再写示例的入口页（把所有演示排成一页）。
3. 建 `examples/<框架>/`（package.json、构建配置），跑 `node scripts/examples/gallery.mjs`、构建、`node scripts/examples/gallery-check.mjs` 截图比对。
4. 官网选择器、代码块自动出现这一项；"框架接入"页按登记表里的 `setup` 显示接入步骤。
